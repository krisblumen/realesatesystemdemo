# TEST-EXECUTION-PLAN
## Proyecto NEW HAUZ

Versión: 1.0
Responsable QA: Sebastián

---

# OBJETIVO

Definir el proceso formal para la ejecución de pruebas durante todo el ciclo de desarrollo.

---

# CICLO DE EJECUCIÓN

1. Recepción de RFC terminado
2. Revisión técnica
3. Preparación de ambiente QA
4. Ejecución de casos de prueba
5. Registro de evidencias
6. Registro de defectos
7. Re-pruebas
8. Regresión
9. Aprobación o rechazo

---

# AMBIENTES

## Development
Validación inicial.

## Staging
QA formal.

## Production
Liberación aprobada.

---

# FLUJO DE DEFECTOS

Nuevo
↓
Asignado
↓
En Corrección
↓
Listo para QA
↓
Validado
↓
Cerrado

---

# CRITERIOS DE EJECUCIÓN

Pruebas críticas:
100% obligatorias

Pruebas altas:
100% obligatorias

Pruebas medias:
mínimo 90%

---

# EVIDENCIAS

Cada prueba debe incluir:

- ID
- Fecha
- RFC
- Resultado
- Captura
- Video (si aplica)

---

# REPORTE DIARIO

- RFC evaluados
- Casos ejecutados
- Pass
- Fail
- Bloqueados
- Riesgos

---

# REPORTE DE SPRINT

- Cobertura
- Bugs encontrados
- Bugs corregidos
- Bugs pendientes
- Resultado final

---

# CRITERIOS DE APROBACIÓN

- Sin bugs bloqueantes
- Sin bugs críticos
- Regresión aprobada
- Evidencias completas

---

# MATRIZ DE ESTADOS

PASS
FAIL
BLOCKED
NOT RUN
